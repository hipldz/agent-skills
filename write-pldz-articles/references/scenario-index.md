# 内置样文索引

这里按原文内容组织已有样文，方便观察作者怎么写，不是新稿必须选择的体裁列表。内置材料来自技术博客，但同样可以为其他主题和用途提供文风参照。用户已提供合适的样文时，优先读用户样文，无需强行匹配下表。

需要内置参照时，根据**当前任务想表达什么**选一两个接近的文件；一个任务可以跨场景。每个文件都内置真实原文片段和对写法的观察，**不需要寻找未打包的原始文章**。

| 场景文件 | 适合什么任务 | 主要观察角度 |
|---|---|---|
| [连续技术教程](scenarios/series-tutorial.md) | 多个概念、代码或配置之间有先后依赖 | 最小例子与概念如何切换，何时细讲配置 |
| [工具分享](scenarios/tool-sharing.md) | 介绍脚本、插件、命令、一个小工具 | 具体动机怎么落到用法和代码 |
| [项目开发记录](scenarios/project-notes.md) | 写功能、项目设计、技术取舍 | 功能说明与真实约束如何交错 |
| [问题分析](scenarios/problem-solving.md) | 写 bug、意料外表现、解决方案 | 从具体现象进入解释，何时承认不确定性 |
| [简短笔记](scenarios/quick-notes.md) | 少量设置或步骤、顺手记录 | 何时一句话就够，不人为扩写 |

没有对应题材时，按表达动作选参照：讲一个选择可看简短笔记，说明缘由可看工具分享，交代取舍可看项目记录。只迁移叙述和语言习惯，不附带原文的技术内容、博客格式或操作步骤；连续正文和非技术文章也无需改成上面五类。

结合 [写法观察](style-observations.md) 阅读真实节选，既看材料怎么排列，也看日常措辞、句子接续、补充条件和收尾方式。涉及事实、引用或作者经历时遵循 [事实约束](fact-boundaries.md)。

场景文件中所写的原文章名只是**已内嵌节选的出处标签**，不是文件名、检索入口或需要另行打开的路径。诸如 CMake、ROS2、Docker 等只代表原文谈论的事物，**不是写作风格类别**。
